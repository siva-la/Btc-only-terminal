Whitepaper ต้นฉบับ (2008)

Satoshi Nakamoto เผยแพร่เอกสาร "Bitcoin: A Peer-to-Peer Electronic Cash System" เมื่อวันที่ 31 ตุลาคม 2008 เพื่อเสนอวิธีแก้ปัญหาการใช้เงินดิจิทัลซ้ำซ้อน (double-spending) โดยไม่ต้องพึ่งคนกลางอย่างธนาคาร

แนวคิดหลักจาก Whitepaper

1. Proof-of-Work Chain: เครือข่ายบันทึกธุรกรรมเป็นบล็อกต่อกันเป็นสายโซ่ แต่ละบล็อกต้องแก้โจทย์คำนวณที่ใช้พลังงานสูง (mining) การจะปลอมแปลงประวัติธุรกรรมต้องคำนวณแข่งกับเครือข่ายทั้งหมด ซึ่งในทางปฏิบัติทำไม่ได้ถ้าผู้ไม่หวังดีไม่ได้ควบคุมพลังประมวลผลเกินครึ่งเครือข่าย

2. Decentralized Timestamp Server: แทนที่จะมีธนาคารกลางคอยยืนยันว่าใครโอนเงินให้ใครก่อน เครือข่าย node ทั่วโลกช่วยกันประทับเวลาธุรกรรมลงในบล็อกที่ทุกคนตรวจสอบได้

3. Incentive Structure: ผู้ขุด (miner) ได้รับเหรียญใหม่เป็นรางวัลจากการสร้างบล็อก บวกค่าธรรมเนียมธุรกรรม เป็นแรงจูงใจให้ช่วยรักษาความปลอดภัยเครือข่ายอย่างสุจริต

4. จำนวนจำกัด 21 ล้านเหรียญ: อัตราการออกเหรียญใหม่ลดลงครึ่งหนึ่งทุกๆ 210,000 บล็อก (ประมาณ 4 ปี) เรียกว่า "halving" ทำให้ปริมาณเหรียญทั้งหมดเข้าใกล้ 21 ล้านแต่ไม่มีวันเกิน

ใครดูแลโค้ด Bitcoin ตอนนี้

หลังจาก Satoshi หายตัวไปในปี 2010 การพัฒนาส่งต่อให้ Gavin Andresen แล้วต่อมาคือ Wladimir van der Laan ปัจจุบัน Bitcoin Core (ซอฟต์แวร์ node หลักที่คนใช้กันมากที่สุด) ไม่มี "ผู้นำ" คนเดียวแล้ว แต่ใช้ระบบ Trusted Keys ที่กระจายอำนาจอนุมัติโค้ดให้กับผู้ดูแลหลายคน ปัจจุบัน (ต้นปี 2026) มีผู้ถือกุญแจที่เชื่อถือได้ 6 คน ได้แก่ Gloria Zhao, Ryan Ofsky, Hennadii Stepanov, Ava Chow และ TheCharlatan ซึ่งเพิ่งได้รับการแต่งตั้งเมื่อเดือนมกราคม 2026 เป็นการขยายกลุ่มครั้งแรกในรอบเกือบ 3 ปี แต่ละคนเชี่ยวชาญเฉพาะด้าน เช่น Gloria Zhao ดูแลเรื่อง mempool และ policy

ความเห็นต่างในวงการพัฒนา

Bitcoin เป็นซอฟต์แวร์โอเพนซอร์สที่ไม่มีใครสั่งการได้ฝ่ายเดียว จึงมีบางประเด็นที่นักพัฒนาเห็นไม่ตรงกัน เช่น Bitcoin Knots ซึ่งเป็นซอฟต์แวร์ node ทางเลือกที่ดูแลโดย Luke Dashjr มีนโยบายบางอย่างต่างจาก Bitcoin Core (เช่นเรื่องขนาดข้อมูลที่แนบในธุรกรรมได้) สะท้อนให้เห็นว่า Bitcoin พัฒนาแบบต้องอาศัยฉันทามติของชุมชน ไม่ใช่คำสั่งจากส่วนกลาง

อยากอ่านฉบับเต็ม

Whitepaper ต้นฉบับความยาว 9 หน้า อ่านได้ฟรีที่ bitcoin.org/bitcoin.pdf — เนื้อหาในหน้านี้เป็นการสรุปแนวคิดหลักด้วยภาษาที่เข้าใจง่ายขึ้น ไม่ใช่การแปลคำต่อคำ

ℹ️ เนื้อหาในหน้านี้เพื่อการศึกษาเท่านั้น ข้อมูลเรื่องผู้ดูแลโครงการและเหตุการณ์ปัจจุบันอาจเปลี่ยนแปลงได้ตามกาลเวลา ตรวจสอบข้อมูลล่าสุดได้ที่ GitHub ของ Bitcoin Core โดยตรง

BTC ONLY คืออะไร

เครื่องมือดูสัญญาณเทรด BTC บน timeframe 1 ชั่วโมง ใช้กลยุทธ์ trend-following ผสม momentum confirmation คำนวณจากข้อมูลราคาจริงของ Binance

กลยุทธ์ทำงานอย่างไร

1. Trend filter: เปรียบเทียบ EMA เส้นเร็วกับเส้นช้า ถ้าเส้นเร็วอยู่เหนือเส้นช้า = เทรนด์ขึ้น
2. Confirmation: รอ MACD ตัดกันเพื่อยืนยันจังหวะแรงส่งเปลี่ยน
3. Momentum filter: ใช้ RSI กรองไม่ให้เข้าตอนราคาสุดขั้วเกินไป
4. Risk management: ใช้ ATR (ความผันผวนเฉลี่ย) กำหนดระยะ Stop-Loss/Take-Profit แบบปรับตามสภาพตลาด ไม่ใช่ตัวเลขตายตัว

Position Sizing

ขนาดโพซิชันคำนวณจาก risk % ที่ตั้งไว้ของทุน หารด้วยระยะห่างจากราคาเข้าไปจุด Stop-Loss แล้ว cap ไม่ให้ margin ที่ต้องใช้เกินเพดานที่ตั้งไว้ — ป้องกันไม่ให้เปิดโพซิชันใหญ่เกินไปตอน SL แคบ

ข้อมูลเก็บที่ไหน

บัญชีทดสอบ (เงินจำลอง), ประวัติเทรด และการตั้งค่าทั้งหมด เก็บไว้ใน localStorage ของเบราว์เซอร์นี้เท่านั้น ไม่ส่งไปเซิร์ฟเวอร์ไหน ถ้าเปลี่ยนเครื่อง/เบราว์เซอร์ หรือล้างข้อมูลเว็บไซต์ ข้อมูลจะหายและเริ่มใหม่

⚠️ คำเตือนความเสี่ยง: นี่คือเครื่องมือดูสัญญาณและบัญชีทดสอบ (paper trading) เพื่อการศึกษาเท่านั้น ไม่ใช่คำแนะนำการลงทุนและไม่รับประกันผลกำไรใดๆ การเทรด crypto futures/perpetual มี leverage ซึ่งมีความเสี่ยงสูงมาก อาจสูญเสียเงินทุนทั้งหมดได้ กลยุทธ์นี้ยังไม่รวม funding rate และค่าธรรมเนียมจริงของ exchange ผลย้อนหลังไม่ได้การันตีผลในอนาคต ควรศึกษาและทดสอบให้มั่นใจก่อนใช้เงินจริงเสมอ
ข้อมูลราคาและกราฟจาก Binance Spot API (BTCUSDT 1H) · รีเฟรชอัตโนมัติทุก 60 วินาที · บัญชีทดสอบและการตั้งค่าบันทึกในเบราว์เซอร์นี้เท่านั้น
